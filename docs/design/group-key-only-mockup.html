Group key only

Mockups for a third mode of enrol_apply: a valid group key enrols at once, and nobody can enrol without one. No application ever waits for a decision. Plan and decisions: group-key-only.md (D1–D8, accepted 2026-11-03). Each screen shows the accepted option; wording is the proposed English string.

0Three modes, one setting

The existing customchar1 gains a third value. The first two behave exactly as they do today. In the third, every route that used to fall back to the queue refuses and writes nothing (D1).

Nothing ('')Every application is reviewed. Keys are ignored.
Key or review ('any')Valid key: enrolled now. No key, a wrong key or a full group: an application waits for a decision.
Key only ('required')Valid key with a place and a seat: enrolled now. Anything else: refused, nothing written, nobody to decide.

1Instance settings (edit_form.php)

One select answers "what does a key do here?" (D2). The managers' notice switch appears only in key-only mode and is off by default (D5). The summary of keyed groups turns into a warning whenever this mode would enrol nobody (P1), and says when applications are still waiting (P2) or when enrol_self accepts the same keys (P7).

3Modal, step 1: the key alone (key only)

The key is a block of its own, not a small inline field (D4): tinted panel, heading-sized label, one sentence, a full-width plain text input that trims what is pasted (D3). Only the key is asked here, so a typo costs nothing. Not a moodleform header: the panel is the key element and an intro, styled by their fitem ids under the plugin's own form class.
